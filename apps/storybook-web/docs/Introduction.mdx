# Design system

Componentes para **web** (React DOM + Tailwind v4) y **mobile** (React Native + Uniwind), con los
mismos tokens, contratos de props y stories.

Cambia el tema con el botón de la barra superior: todos los componentes siguen los tokens
semánticos (`background`, `foreground`, `primary`…), así que no hay nada que cambiar por componente.

## Cómo está organizado

- **Components**: el catálogo. Cada componente tiene una implementación web (la que ves aquí) y una native.
- Las stories marcadas `web-only` prueban comportamiento del navegador (teclado, foco). Las del resto se comparten con el Storybook native.

## Por dónde empezar

- **Foundations**: los tokens (colores con sus reglas de uso, tipografía, espaciado, radios, elevación y movimiento).
- **Components** y **Patterns**: cada componente muestra sus variantes y estados, y cita en su descripción la pantalla de una app real que lo inspiró.
- **Guidelines**: accesibilidad, reglas para escribir código que sirva en web y native, diferencias entre plataformas y cómo contribuir.

## Dirección visual

Neutral y preciso: grises con un matiz de la marca, una sola tinta de acento (índigo), superficies por capas (`background` → `card` → `popover`) y una jerarquía tipográfica clara. Los estados (éxito, advertencia, información, error) usan siempre los cuatro tokens `X`, `X-foreground`, `X-subtle` y `X-subtle-foreground`.
